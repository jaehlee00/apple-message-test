The supplied demonstration components are working React Native code. Your existing component library has not been supplied; replace registry entries when it is available. Keep the source-evidence panel, raw values and null metadata intact.

Why a separate JavaScript entry?

Importing your whole app entry can start navigation, analytics, push SDKs or login code that expects a normal app process. The Messages entry imports the shared visual components and only the dependencies they need.

What does the native bridge do?

getState reads review state; confirm invokes the mock API; cancel changes local state without an API call; expand requests the larger Messages view; insert stages a message for the user to send. Each call identifies its own active message context.

The current adapter uses RN's legacy native-module interface. Check its interoperability against your exact RN version. A codegen-only project can implement the same five-method contract as a TurboModule.

03 / Exercise the actual shared components

Start with the interactive demonstration.

1

Open the component lab

Open react-native-demo.html. Select bar, line, pie and data. Choose Q4 and inspect its date, raw value and calculated flag. Change the preview size; the same components resize.

Expected: 76441000000 USD for Q4; quarter end 2025-06-30; Fiscal; calculated true.

2

Exercise confirmation and cancellation

Choose confirmation, then Cancel: the mock API counter stays zero. Start a new demo session and Confirm: the counter becomes one and a mock receipt appears. Enable “Fail first confirmation” to inspect the failure and retry with the same request ID.

The browser mock does not make HTTP requests. In the native path, the configured adapter posts to the existing mock endpoint.

04 / Integrate with the existing iOS project

Add the native shell around shared UI.

4

Copy only the integration source

In your app repository, create integrations/messages. Copy the supplied src, ios, and index.messages.js there. Keep your existing app entry, package file, lockfile, Metro and Babel configuration. Add compatible chart dependencies only if needed.

Both the full-app screen and extension entry import the same clientComponents registry. Wrap your own components at that seam.

5

Create a Messages extension target

Open your app's iOS workspace in Xcode. Choose File → New → Target → iMessage Extension. Name it ChartMessagesRN and embed it in the existing app. A target is a separately built part of the package.

Add the provided Swift/Objective-C host files and the three Swift files from ios/Shared to this target. Use the supplied plist's extension point and principal class, and remove any generated storyboard setting. Add the JSON and image to Copy Bundle Resources.

Expected: your regular app plus one embedded Messages extension, each with its own bundle ID.

6

Link RN and build the separate bundle

Merge the reviewed Podfile.fragment.rb into the app's Podfile. Run bundle exec pod install with its existing Ruby setup. Keep extension API safety checks enabled and audit native dependencies.

Add an extension-only Run Script:

/bin/sh "$SRCROOT/../integrations/messages/ios/bundle-messages.sh"

This produces messages.jsbundle from the separate entry. The normal app retains its own bundle. The host loads a bundled file even in Debug; it does not depend on a live Metro server.

See react-native/README.md for exact source membership, bridging header, deployment target and runtime notes.

Build compatibility must be established. The components were checked in the JavaScript toolchain. The native host is source prepared for integration; it has not been compiled with Apple SDKs here. Exact RN, CocoaPods, dependency-provider and extension API compatibility are remaining checks.
05 / Existing delivery path

Keep the message contract on the server.

7

Configure the selected app identity and origin

Use twilio/config/react-native.env.example. Set the existing app's App Store ID, signing team and the new extension bundle ID. Put the deployed HTTPS origin in this path's ios/Shared/ChartModel.swift.

The native code validates the received component URL and exact chart revision, then loads /chart-manifest. Confirm calls /mock-confirm; the receipt is visibly marked mock. No app-side Twilio credentials are needed.

Twilio AMB remains an independent gate

The exact account-supported custom interactive message envelope is still unverified. React Native changes how the installed extension draws its interface; it does not supply that missing provider contract. Keep live delivery disabled until the supported mapping is obtained and tested.

Agent install links, readiness detection and authenticated result callbacks follow the existing integration TODOs. The current native result stays in the component; it does not automatically notify the agent or send another bubble.
